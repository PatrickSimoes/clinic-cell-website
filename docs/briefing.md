# Briefing original — Site institucional ClinicCell

> Documento de requisitos entregue no início do projeto (mantido aqui como referência).

Atue como um desenvolvedor Frontend Sênior e Web Designer especializado em interfaces institucionais, experiência mobile-first, SEO local e performance.

Seu objetivo é desenvolver um site institucional profissional para a **ClinicCell**, uma empresa de assistência técnica e serviços relacionados a celulares, utilizando a identidade visual fornecida como principal referência de design.

Não quero um site com aparência de template genérico ou de interface gerada por inteligência artificial. O projeto precisa ter personalidade visual, consistência com a marca e decisões de design intencionais.

---

- Nome: ClinicCell
- Segmento: Assistência técnica de celulares.
- Desde: 2011.

---

## 2. Direção de design

Quero uma interface com aparência de empresa real, estabelecida e profissional.

Referências conceituais:

- Sites institucionais de empresas de tecnologia.
- Empresas especializadas em manutenção de equipamentos eletrônicos.
- Design editorial limpo.
- Interfaces modernas, mas sem exageros.

### Evitar completamente:

- Aparência de landing page genérica de IA.
- Gradientes exagerados.
- Glassmorphism desnecessário.
- Muitos cards com bordas arredondadas.
- Emojis como ícones.
- Animações excessivas.
- Textos genéricos de marketing.
- Elementos decorativos sem propósito.
- Layout excessivamente simétrico e repetitivo.

Utilize tipografia moderna, boa hierarquia visual, espaçamento consistente e ícones SVG de qualidade.

O resultado precisa parecer desenvolvido por um designer profissional que estudou a identidade da ClinicCell.

---

## 3. Estratégia mobile-first

O site será acessado principalmente por celulares.

Portanto, desenvolva primeiro para dispositivos móveis.

Requisitos:

- Layout responsivo.
- Navegação simples.
- Botões com áreas de toque adequadas.
- Textos legíveis sem necessidade de zoom.
- Imagens otimizadas.
- Menu mobile funcional.
- WhatsApp facilmente acessível.
- Carregamento rápido.
- Boa experiência em diferentes tamanhos de tela.

Não faça simplesmente uma versão desktop reduzida para celular. Pense a experiência mobile desde o início.

---

## 4. Estrutura do site

Desenvolva uma página institucional completa, organizada nas seguintes seções:

### 4.1. Header

- Logo ClinicCell.
- Navegação objetiva.
- Links para serviços, sobre e contato.
- Botão de orçamento pelo WhatsApp.
- Menu mobile funcional.

O header deve ser discreto, elegante e consistente com a identidade visual.

### 4.2. Hero section

A primeira dobra precisa comunicar imediatamente o que a empresa faz.

Título sugerido:

"Seu celular merece cuidado especializado."

Subtítulo:

"Assistência técnica de celulares em São José dos Pinhais. Atendimento próximo, experiência e compromisso com cada reparo."

Destaque visual para:

- Logo ClinicCell.
- Informação "Desde 2011".
- Localização em São José dos Pinhais.
- Botão principal: "Solicitar orçamento".
- Botão secundário: "Conhecer serviços".

O botão principal deve direcionar para o WhatsApp.

A composição visual deve ser forte, sem utilizar imagens genéricas de pessoas sorrindo ou equipes fictícias.

### 4.3. Serviços

Criar uma seção apresentando os serviços oferecidos.

Importante: não invente serviços que ainda não foram confirmados pelo proprietário.

Inicialmente, prepare a estrutura para apresentar serviços como:

- Troca de tela.
- Troca de bateria.
- Reparo de conectores.
- Manutenção de smartphones.
- Reparo de aparelhos.

Os serviços devem ser facilmente editáveis e só devem aparecer publicamente após confirmação.

Cada serviço pode ter um ícone SVG e uma descrição curta.

### 4.4. Sobre a ClinicCell

Apresentar a empresa destacando sua trajetória desde 2011.

Texto conceitual:

"Desde 2011, a ClinicCell trabalha com o compromisso de oferecer soluções para quem precisa cuidar do seu celular. Nossa proposta é unir experiência, atenção aos detalhes e atendimento próximo."

Não invente certificações, quantidade de clientes atendidos, qualificações ou garantias.

### 4.5. Diferenciais

Criar uma seção para comunicar os diferenciais reais da empresa.

Priorizar:

- Experiência desde 2011.
- Atendimento próximo.
- Localização em São José dos Pinhais.
- Comunicação direta pelo WhatsApp.

Não utilizar promessas sem comprovação.

### 4.6. Localização

Criar uma seção com:

- Endereço: Rua Annelise Gellert Krigsner, 2884, bairro Iná, São José dos Pinhais - PR.
- Botão para abrir localização no Google Maps.
- Referência visual ao mapa.
- Informações de contato.

Link do Google Maps:
https://maps.app.goo.gl/MB3FU8HECsMP754W9

### 4.7. CTA final

Criar uma seção de conversão com destaque visual.

Título:

"Precisa de ajuda com seu celular?"

Texto:

"Entre em contato com a ClinicCell e consulte as opções de atendimento."

Botão:

"Falar com um especialista"

Direcionar para o WhatsApp.

Incluir:

## 6. SEO local

Essa é uma parte fundamental do projeto.

O site precisa ser desenvolvido pensando em buscas orgânicas no Google.

Palavras-chave prioritárias:

- Assistência técnica de celular em São José dos Pinhais.
- Conserto de celular em São José dos Pinhais.
- Assistência técnica de celular no bairro Iná.
- Troca de tela de celular.
- Troca de bateria de celular.
- Manutenção de smartphones.

Implementar:

- Title otimizado.
- Meta description.
- URLs amigáveis.
- HTML semântico.
- Hierarquia correta de H1, H2 e H3.
- Open Graph.
- Sitemap XML.
- Robots.txt.
- Canonical URL.
- Schema.org com LocalBusiness e o tipo de negócio adequado.
- Dados estruturados de endereço e telefone.
- Otimização de imagens.
- Links internos.

Exemplo de title:

"ClinicCell | Assistência Técnica de Celulares em São José dos Pinhais"

Exemplo de description:

"Precisa de assistência técnica para seu celular em São José dos Pinhais? Conheça a ClinicCell, no bairro Iná. Entre em contato pelo WhatsApp."

Não repetir palavras-chave artificialmente.

O conteúdo deve ser natural e realmente útil para quem procura assistência técnica.

## 7. Tecnologias e hospedagem

O site será hospedado inicialmente no GitHub Pages.

Priorize uma arquitetura estática, sem necessidade de backend.

Sugestão de stack:

- Astro ou Vite com React e TypeScript.
- HTML semântico.
- CSS organizado.
- Componentização.
- Lucide para ícones.
- Estrutura preparada para manutenção e evolução.

Escolha a tecnologia que melhor se encaixa na hospedagem estática do GitHub Pages.

Requisitos:

- Build estático.
- Nenhuma dependência de servidor Node.js em produção.
- Nenhuma API obrigatória.
- Nenhum banco de dados.
- Compatibilidade com GitHub Pages.
- Configuração de GitHub Actions para deploy automático.
- Tratamento correto de base path caso o projeto utilize um repositório em vez de um domínio próprio.

Não utilizar recursos que dependam de um servidor tradicional.

## 8. Performance e qualidade

Priorizar:

- Lighthouse com boas pontuações.
- Core Web Vitals.
- Imagens em WebP ou AVIF.
- Lazy loading.
- Fontes otimizadas.
- CSS enxuto.
- JavaScript mínimo.
- Acessibilidade.
- Contraste adequado.
- Navegação por teclado.
- Metadados completos.

---

## 9. Organização do projeto

Estruture o código de maneira profissional.

Separar:

- Componentes.
- Layout.
- Seções.
- Estilos.
- Assets.
- Configurações.
- Conteúdo institucional.

Centralizar informações comerciais em uma configuração facilmente editável, evitando espalhar telefone, endereço e nome da empresa pelo código.

A logo fornecida deve ser incluída nos assets do projeto.
